  SISTEMA DE GESTIÓN DE HORARIOS PARA SALONES DE BELLEZA
═══════════════════════════════════════════════════════════════════════════════

📋 DESCRIPCIÓN DEL PROYECTO
═══════════════════════════════════════════════════════════════════════════════

Este es un sistema completo de gestión para salones de belleza que permite:
- Administrar citas y agendas de trabajo
- Gestionar clientes, personal y servicios
- Control de inventario
- Sistema de reservas públicas por URL personalizada
- Panel de administración completo
- Autenticación y autorización de usuarios

🏗️ ARQUITECTURA DEL PROYECTO
═══════════════════════════════════════════════════════════════════════════════

BACKEND:
- Node.js + Express + TypeScript
- Base de datos PostgreSQL con Prisma ORM
- Autenticación JWT
- CORS habilitado para desarrollo

FRONTEND:
- Vue.js 3 con Vue Router
- Tailwind CSS para estilos
- Single Page Application (SPA)

ESTRUCTURA DE CARPETAS:
├── src/                        # Backend (TypeScript)
│   ├── controllers/            # Controladores de negocio
│   ├── routes/                 # Rutas de la API
│   ├── middleware/             # Middlewares (auth, etc.)
│   └── index.ts               # Punto de entrada del servidor
├── frontend/                   # Frontend (Vue.js)
│   └── src/
│       ├── views/             # Páginas principales
│       ├── router/            # Configuración de rutas
│       └── components/        # Componentes reutilizables
├── prisma/                     # Esquema y migraciones de BD
└── package.json               # Dependencias del backend


🚀 CÓMO ARRANCAR EL PROYECTO
═══════════════════════════════════════════════════════════════════════════════

REQUISITOS PREVIOS:
- Node.js (v14 o superior)
- PostgreSQL instalado y corriendo
- npm o yarn

PASO 1: CONFIGURAR VARIABLES DE ENTORNO
----------------------------------------
Crear un archivo .env en la raíz del proyecto con:

DATABASE_URL="postgresql://usuario:contraseña@localhost:5432/nombre_db"
JWT_SECRET="tu_clave_secreta_aqui"
PORT=3000
SMTP_USER="tu_email@gmail.com"
SMTP_PASS="tu_app_password_de_gmail"
WHATSAPP_TOKEN="tu_token_de_whatsapp_business_api"
WHATSAPP_PHONE_ID="tu_phone_id_de_whatsapp"

PASO 2: INSTALAR DEPENDENCIAS DEL BACKEND
------------------------------------------
npm install

PASO 3: CONFIGURAR BASE DE DATOS
---------------------------------
npx prisma migrate dev
npx prisma generate

PASO 4: ARRANCAR EL BACKEND
----------------------------
npm run dev

El servidor estará corriendo en http://localhost:3000

PASO 5: INSTALAR DEPENDENCIAS DEL FRONTEND
-------------------------------------------
cd frontend
npm install

PASO 6: ARRANCAR EL FRONTEND
-----------------------------
npm run serve

El frontend estará corriendo en http://localhost:8080


📊 BASE DE DATOS - MODELOS
═══════════════════════════════════════════════════════════════════════════════

USER (Usuarios del sistema)
- id, email, password, role (ADMIN/WORKER)
- name, phone
- resetToken, resetTokenExpiry (para recuperación de contraseña)
- Relaciones: administra un salón o trabaja en uno

SALON (Salones de belleza)
- id, name, slug (URL única), address, phone
- adminId (propietario)
- Relaciones: servicios, clientes, empleados, configuración

CONFIG (Configuración del salón)
- Horarios de apertura/cierre
- Intervalos de servicio
- Permisos (confirmación de citas, modificaciones)

SERVICE (Servicios ofrecidos)
- name, description, duration (minutos), price
- Vinculado a un salón específico

CLIENT (Clientes)
- name, phone
- Vinculado a un salón

EMPLOYEE (Empleados/Estilistas)
- name, role
- Vinculado a un salón

APPOINTMENT (Citas)
- clientId, stylistId, serviceId
- startTime, endTime
- status (PENDING, CONFIRMED, CANCELLED, COMPLETED)

INVENTORY (Inventario)
- productName, quantity, lowStockThreshold
- Control de productos del salón

PAYMENT (Pagos)
- appointmentId, amount, paymentMethod (CARD, CASH, BIZUM)
- status (PENDING, COMPLETED)


🛣️ RUTAS DE LA API (BACKEND)
═══════════════════════════════════════════════════════════════════════════════

AUTENTICACIÓN (/auth)
------------------------------------
POST   /auth/register          - Registrar nuevo usuario/salón
POST   /auth/login             - Iniciar sesión (devuelve JWT token)
POST   /auth/forgot-password   - Solicitar restablecimiento de contraseña
POST   /auth/reset-password    - Restablecer contraseña con token

CITAS (/appointments) [Requiere autenticación]
------------------------------------
GET    /appointments           - Listar todas las citas del salón
GET    /appointments/:id       - Obtener cita específica
POST   /appointments           - Crear nueva cita
PUT    /appointments/:id/status - Actualizar estado de cita

SERVICIOS (/services) [Requiere autenticación]
------------------------------------
GET    /services               - Listar servicios del salón (filtrado automático)
GET    /services/:id           - Obtener servicio específico
POST   /services               - Crear nuevo servicio
PUT    /services/:id           - Actualizar servicio (valida propiedad)
DELETE /services/:id           - Eliminar servicio (valida propiedad)

CLIENTES (/clients) [Requiere autenticación]
------------------------------------
GET    /clients                - Listar clientes del salón (filtrado automático)
GET    /clients/:id            - Obtener cliente específico
POST   /clients                - Crear nuevo cliente
PUT    /clients/:id            - Actualizar cliente
DELETE /clients/:id            - Eliminar cliente

SALÓN (/salon) [Requiere autenticación]
------------------------------------
GET    /salon/:slug            - Obtener información del salón por slug

PÚBLICO (/public) [Sin autenticación]
------------------------------------
GET    /public/:slug           - Ver página pública del salón
GET    /public/:slug/slots     - Obtener horarios disponibles para reservar

🔐 FLUJO DE AUTENTICACIÓN
═══════════════════════════════════════════════════════════════════════════════

1. El usuario se registra en /auth/register
   - Se crea un usuario y un salón automáticamente
   - El usuario es asignado como ADMIN del salón
   - Se genera un slug único para el salón

2. El usuario inicia sesión en /auth/login
   - Se valida email y contraseña
   - Se devuelve un token JWT

3. El frontend guarda el token en localStorage

4. Para cada petición protegida, el frontend envía el token en headers:
   Authorization: Bearer <token>

5. El middleware de autenticación valida el token
   - Decodifica el JWT
   - Verifica que el usuario existe
   - Permite o deniega el acceso


🌐 SISTEMA DE SLUG PÚBLICO
═══════════════════════════════════════════════════════════════════════════════

Cada salón tiene una URL única basada en su slug:
- Ejemplo: /salon/mi-salon-belleza

Los clientes pueden:
1. Acceder a esta URL desde cualquier dispositivo
2. Ver información del salón (nombre, servicios, horarios)
3. Seleccionar un servicio
4. Ver horarios disponibles
5. Reservar una cita proporcionando sus datos

Esto permite que los salones compartan su link en redes sociales,
tarjetas de visita, etc.

⚠️ NOTAS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════════

1. NO OLVIDAR configurar el archivo .env antes de arrancar
2. PostgreSQL debe estar corriendo
3. Ejecutar migraciones antes del primer uso
4. El puerto 3000 y 8080 deben estar disponibles
5. En producción, cambiar CORS y variables de entorno
6. El JWT_SECRET debe ser una cadena segura y aleatoria
7. Para Gmail SMTP, usar contraseña de aplicación (no contraseña normal)
8. WhatsApp Business API requiere configuración en Meta Business Suite
9. Los tokens de restablecimiento expiran en 1 hora
10. Sistema multi-tenant: cada salón solo ve sus propios datos
